## 一、建议结论

**先迁移少量独立工具和必要的适配层，不直接搬入整套后端。**

对当前论文，最有价值的是 Word 样式参考、导出前检查、结果与正文一致性检查，以及按需的文献检索。现有 MCP 已经能够读取文件、执行脚本和展示产物，没有必要仅为使用这些能力再启动一套带数据库、自动恢复和代码执行接口的服务。

建议本次审核只批准下面的 **A 阶段（离线工具）**；B 阶段的联网服务、C 阶段的后端分别授权。

### 2.2 后端：有可借鉴的结构，但存在迁移前必须处理的问题

以下位置均相对于来源目录，行号对应本轮读取的版本。

| 问题 | 证据位置 | 对迁移的影响 |
| --- | --- | --- |
| 失败步骤后仍可能发出完成事件，并把工作流标记 completed | `backend/services/workflow_engine.py:1002–1017` | 不能把界面“完成”当作产物验收；应失败中止或显式记录 partial/failed |
| 用户检查点超时后自动继续，调用方把缺省 action 当 approve | 同文件 `:799–811`、`:960–970` | 与“先审核再执行”冲突；超时必须暂停，不能自动批准 |
| 启动即初始化/修改数据库、恢复旧任务、清理进程和旧目录 | `backend/main.py:26–43`；`backend/services/state_store.py:56–159` | 不能拿正式论文目录或旧 `.mhagent` 做启动测试；必须禁用自动恢复与自动清理 |
| Runner 默认跳过权限确认 | `backend/services/claude_runner.py:485–493` | 不适合原样接入重要文件；应改为受限任务、明确审批和受控执行 |
| 多处关闭 TLS 主机名/证书校验 | `tools/reviewer_client.py:68–70`；`backend/services/llm_client.py:76–78,197–199`，另见图像工具 | 可能暴露论文和凭据；校验失败应报错，不降级绕过 |
| 文献工具存在硬编码疑似 API 凭据、第三方默认入口与不安全 TLS 回退 | `tools/scholar_fetch.py:49–85,117–119` | 不使用、不传播该值；迁移前移除，由所有者核实是否需要轮换 |
| 编辑器和产物路由用字符串前缀判断路径归属 | `backend/routers/editor.py:114–119`；`backend/routers/artifacts.py:413,496` | 相邻同前缀目录可能被误接受；应使用规范化路径的目录归属检查，处理 Windows 盘符及链接 |
| 宽松 CORS，已查路由未见统一调用鉴权；同时有文件写入、脚本执行接口 | `backend/main.py:49–55`；`backend/routers/editor.py:1233–1272` | 即使只在本机运行，也不能把这些接口视为安全隔离；需鉴权、来源约束及操作白名单 |
| 设置字段脱敏不完整，数据库保存字符串值 | `backend/routers/settings.py:16–29`；`backend/db/schema.sql` | `editor_ai_api_key` 不在脱敏列表；不能迁移旧设置库或直接返回任意设置字段 |
| 编辑器导入不存在的 `claude_runner` 名称，实际单例名为 `_runner` | `backend/routers/editor.py:1010,1158`；`backend/services/claude_runner.py` 末尾 | 静态接口不一致，相关编辑/停止路径需修复和测试 |
| `auto` 导出分支走缺失的 Node 引擎，而非已验证的 Pandoc | `backend/routers/docx_export.py:168–195` | 不能默认复用此接口；必须显式选择真实可用的导出链路 |
| ZIP 工作区导入未对成员路径做完整归属检查 | `backend/routers/workflows.py:450–468` | 引入导入功能前需处理路径越界、链接、压缩包大小及解压总量限制 |

另需统一子进程环境传递、配置入口、取消任务行为和数据库连接生命周期，不能只修一处 import 就宣布后端可用。

**已做的隔离验证：**仅抽取函数 AST，在本地用虚构路径、合成字段和模拟数据库/任务运行；没有导入或启动真实后端。复现了：
1. 路径前缀检查接受相邻同前缀目录；
2. 检查点超时被默认批准；
3. 模拟步骤失败后仍产生 `step_completed` 和 `workflow_completed`；
4. 合成的 `editor_ai_api_key` 未被脱敏。

这证明上述逻辑问题存在，**不代表真实服务被攻击，也不是后端端到端验收**。

结束前对本轮读取的 92 个来源/目标文件核对 SHA-256，均未变化；目标项目的 `tools/`、`backend/`、拟议 `apps/modex_backend/` 均尚未创建。仅新增本方案文档。

## 三、分阶段迁移方案

### A 阶段：离线工具，建议优先批准

目标：让少量 skills 真正能服务论文，不联网、不启服务、不改实验结果。

**拟迁移/新增：**

1. 迁移并小幅适配 `derive_reference_from_docx.py`，输出样式参考 JSON/Markdown；仅处理明确指定的输入。
2. 重新实现轻量字数与 Markdown 导出前检查，覆盖标题、表格列数、围栏、图片路径、引用编号结构等。只出报告，不自动改稿。不能宣称检查已证明数值真实性或学术结论正确。
3. 为现有 `scripts/build_draft.py`、`scripts/md2docx.py` 做受控调用适配，而不是引入缺失的导出引擎。
4. 增加工具清单与路径映射，告诉 skills 当前哪些能力已实现。第一阶段不覆盖原始 SKILL.md 或已有 `.claude/skills/`。

**拟采用的目标结构（仅方案，现在尚未创建）：**

```text
tools/
  modex/
    README.md
    provenance.json                 # 来源路径、文件 hash、修改记录
    derive_reference_from_docx.py    # 经适配的离线候选
    paper_checks.py                 # 新实现，不复制注释空壳
    export_adapter.py               # 调用现有生成器
configs/
  modex-tools.json                  # 非敏感配置；输入/输出和工具路径
scripts/
  modex_tools.py                    # 一个明确的 CLI 入口
requirements-modex-tools.txt        # 独立工具依赖清单，不改训练依赖
outputs/
  modex/                           # 报告、样式参考、试导出文档
logs/
  modex/                           # 运行记录，不记录密钥
```

默认使用已经复制的 `runtime/python/python.exe`、`runtime/pandoc/pandoc.exe` 的绝对路径；不修改全局 PATH，不更换论文训练环境。

当前 `md2docx.py` 在模块顶层读取参数并执行，因此适配器应通过受控子进程调用，而不是直接 import。固定仓库根目录为 cwd，正确解析图片路径；输入白名单、输出不可与输入相同、设置超时、默认不覆盖已有产物。

若调用 `build_draft.py` 会更新合并稿，必须明确列入批准范围；初次测试应使用测试副本，不能把当前正式稿当作试验输出。第一阶段不自动把新样式 profile 接入原生成器。

**预计需改的现有文件：**默认不改分析代码、训练配置、正文与原始技能；可补充 skills README 的调用示例。是否增加 `.gitignore` 规则应在实施清单中明确列出，不悄悄修改。

### B 阶段：联网工具，单独授权

在 A 验收后，再选择文献检索和/或外部评审：

- `scholar_fetch.py`：去掉硬编码凭据和默认付费中转；数据源显式配置，设置超时、重试上限、缓存、限流和来源记录。
- `reviewer_client.py`：仅接受用户配置的服务，修复 TLS、URL `/v1` 拼接和响应校验；限制文本量、超时、费用预算和轮数，必要时脱敏。
- 先用本地 mock 验证，再由用户批准一次真实请求。文献检索授权不等于上传整篇论文授权。
- 不复制源码中的密钥、旧线程记录、`.mhagent` 数据库、用户设置或访问令牌。对话记录需明确留存策略。

图像生成与通知工具暂不列入推荐首批范围。

### C 阶段：后端，按确实需要再做

如果以后需要浏览器界面、任务历史和多个任务排队，优先建设一个**精简本地后端**，复用经过审查的结构和离线工具，不复制原执行引擎的全部默认行为。

- 包路径拟为 `apps/modex_backend/`，使用包内显式导入和统一配置，避免裸 `config`、`services` 与论文代码冲突。
- 初期只提供健康检查、工具清单、只读任务记录和受限工具任务接口。
- 不开放任意脚本执行、任意文件写入、自动训练、自动恢复、自动清理或任意反向代理。
- 每个任务使用独立工作目录；正式数据和论文作为只读输入，结果进入单独输出目录。普通目录副本不等于操作系统级沙箱；执行不可信代码需更强隔离。
- 使用全新数据库，不导入旧 `.mhagent`、旧 PID 清单、清理清单和账号配置。
- 默认绑定本机回环地址，限定 CORS/Host，给有副作用的接口加认证、授权和请求校验；不默认开放局域网或公网。
- 固定状态机：失败不发完成事件；审批超时暂停；取消确实停止对应子进程；不根据旧 PID 盲目结束进程。
- 先以 mock runner 验证完整状态流，再申请一次真实模型执行测试。

原 `models`、schema 和任务/日志设计可借鉴，但需清理遗留字段、敏感信息保存方式和导入路径。文件解析逻辑可提取成独立 helper；`state_store.py`、`workflow_engine.py`、`claude_runner.py` 不能不经整改整包接入。

Electron、原前端 bundle、激活绕过/加解密透传代码不在建议迁移范围。若需要原样应用体验，应另作为独立应用修复和测试，而不是塞进论文主工作区。

## 四、验收与回退

### A 阶段必须满足

- 各工具具备真实 CLI、缺输入时非零退出、稳定输出格式；不能以空脚本 exit 0 验收。
- 用中文文件名、空格路径、缺图片、表格列数错误和不同 cwd 的样例测试。
- Word 试导出文件可打开，预期图片/表格存在；样式参考提取结果可读，源模板未改变。
- 输入和输出范围明确，越界路径/不允许覆盖被拒绝；不会无意扫描或复制约 8 GB runtime。
- `data/`、预测结果、现有正文和正式 Word 的 hash 在测试前后保持不变；工具输出放到新目录。
- 不访问模型 API，不安装未批准的依赖，不修改训练环境。

### B/C 阶段额外验收

- TLS 失败不会降级跳过校验；日志和报告没有密钥。
- 请求目的地址、数据源、发送内容及预算均明确。
- 后端未授权调用、路径越界、异常中断、失败步骤、审批超时、取消与重启均有负向测试。
- 不自动恢复旧任务、不删除未经验证的目录、不触碰旧数据库或其他进程。

实施时先记录基线 hash，新增工具使用独立目录，保留原生成链路。回退以撤销新增适配和配置为主；不通过重置论文仓库来回退。

`runtime/` 约 8 GB，且当前未被 `.gitignore` 排除。后续如允许调整忽略规则，应排除 runtime、运行状态和敏感配置，不排除希望版本管理的工具源码。**迁移与 Git commit/push 是独立动作，本方案不包含提交或推送。**

## 五、请审核的范围
